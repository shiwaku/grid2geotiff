# grid2geotiff

航空レーザ計測のグリッドデータ（XYZ 座標値テキスト）を GeoTIFF に変換する CLI。

```console
$ grid2geotiff convert data/raw -o data/out -j 4
変換 4 ファイル -> data/out  (CRS は図郭番号から判定 / JGD2011)
  OK   08LE2134.txt  800x600 @ 0.5m  点 478,294  欠損 1,706 (0.36%)  CRS EPSG:6676（1/500 図郭番号から推定）  -> 08LE2134.tif
  OK   08LE2135.txt  800x600 @ 0.5m  点 480,000  欠損 0 (0.00%)  CRS EPSG:6676（1/500 図郭番号から推定）  -> 08LE2135.tif

変換: 成功 2 / 失敗 0 / 計 2
```

できること。

- **位置がずれない。** セル中心で記録された座標を半セルずらして配置するので、出力が国土基本図の図郭境界にぴったり載る
- **座標系を指定しなくてよい。** ファイル名が図郭番号なら EPSG を自動で判定する
- **おかしな入力は黙って通さない。** 格子に載っていない点群は内挿せずエラーにする
- **大量の図郭を1枚にまとめられる。** 何千枚でもメモリに載せずに結合する
- **仕様に適合しているか確かめられる。** 林野庁・国土地理院のマニュアルの条項と照らして点検する

なぜそうしているのかは [設計メモ](docs/design.md) に書いてある。

## インストール

```console
pip install -e .
```

Python 3.10 以上。依存は rasterio / numpy / pandas / click だけで、GDAL の Python バインディングは要らない。

`merge --clip` でベクタファイルの範囲を使う場合だけ fiona を足す。

```console
pip install -e ".[clip]"
```

## はじめの一歩

図郭番号がファイル名になっているグリッドデータなら、これだけで変換できる。

```console
grid2geotiff convert <入力ディレクトリ> -o <出力ディレクトリ>
```

ファイル名が図郭番号でないなら、座標系を教える。

```console
grid2geotiff convert dsm.txt -o out --crs EPSG:6676
```

うまくいかないときは [エラーが出たとき](#エラーが出たとき) を見る。

## コマンド

### convert — GeoTIFF に変換する

```console
grid2geotiff convert <入力...> -o <出力先> [--crs <EPSG>]
```

入力にはファイルのほかディレクトリも指定できる（再帰探索）。`--crs` を省略するとファイル名の図郭番号から判定する。

| オプション | 既定 | 説明 |
|---|---|---|
| `-o, --out-dir` | 必須 | GeoTIFF の出力先 |
| `--crs` | 図郭番号から判定 | 入力座標の参照系（例 `EPSG:6676` = JGD2011 平面直角座標系第8系） |
| `--datum` | `jgd2011` | 図郭番号から判定するときの測地系。`jgd2011` / `jgd2000` |
| `--res` | 自動推定 | 格子間隔 [m]。`0.5` か `0.5,0.5` |
| `--nodata` | `-9999` | 出力の NoData 値 |
| `--dtype` | `float32` | `float32` / `float64` / `int16` / `int32` |
| `--compress` | `deflate` | `deflate` / `lzw` / `zstd` / `none`（予測子2つき） |
| `--blocksize` | `256` | タイル化のブロックサイズ |
| `--delimiter` | 自動判定 | `space` / `comma` / `tab` / `semicolon` |
| `--columns` | `0,1,2` | X,Y,Z の列番号（0 始まり）。4列以上のファイルにも使える |
| `--input-nodata` | なし | 入力側の欠測値。複数指定可 |
| `--tolerance-ratio` | `0.01` | 格子からのずれの許容量（格子間隔に対する比） |
| `--min-fill-ratio` | `0.01` | セル数に対する点数の下限。下回れば格子とみなさない |
| `-j, --jobs` | `1` | 並列処理数 |
| `--overwrite` | off | 既存の出力を上書き |

### inspect — 変換せずに点検する

大量の図郭を変換する前に、格子間隔の食い違いや不規則点群の混入を洗い出す。出力は作らない。

```console
$ grid2geotiff inspect data/raw -j 4
点検 4 ファイル
  OK   08LE2134.txt  800x600 @ 0.5m  点 478,294  欠損 1,706 (0.36%)  X 5600.00..6000.00 Y -37200.00..-36900.00  CRS EPSG:6676（1/500 図郭番号から推定）
```

`convert` と同じ判定を行うので、**どの CRS が埋め込まれるかを事前に確認できる**。点検では CRS を判定できなくても失敗にはせず、理由を添えて報告する。

オプションは `convert` の表のうち出力に関わらないもの（`--crs` / `--datum` / `--res` / `--delimiter` / `--columns` / `--input-nodata` / `--tolerance-ratio` / `--min-fill-ratio` / `-j`）がそのまま使える。

### merge — 図郭を1枚に結合する

```console
$ grid2geotiff merge data/out -o mosaic.tif
結合 6 ファイル -> mosaic.tif
  OK   1,600x1,800 @ 0.5m  被覆率 100.00%  -> mosaic.tif
```

1/500 図郭は 400m × 300m なので、県域だと図郭が万単位になる。QGIS はファイル数が 100 を超えると重くなるため、扱いやすい大きさにまとめる。

| オプション | 既定 | 説明 |
|---|---|---|
| `-o, --out` | 必須 | 出力ファイル |
| `--nodata` | `-9999` | 出力の NoData 値。図郭間で不揃いでもこの値に統一する |
| `--compress` | `deflate` | `deflate` / `lzw` / `zstd` / `none` |
| `--blocksize` | `256` | タイル化のブロックサイズ |
| `--bounds` | なし | 切り出す範囲 `xmin,ymin,xmax,ymax`。格子に合わせて外側へ丸める |
| `--clip` | なし | 切り出す範囲をベクタファイルの範囲から取る（fiona が要る） |
| `--min-coverage` | `0.05` | 出力セル数に対する入力の被覆率の下限 |
| `--vrt-only` | off | GeoTIFF を書かず VRT だけを出力する |
| `--keep-vrt` | off | GeoTIFF に加えて同じ名前の `.vrt` も残す |
| `--overwrite` | off | 既存の出力を上書き |

VRT は実データを持たない小さな XML で、QGIS がそのまま開ける。**実体を作らないので一瞬で終わり、容量も食わない。**

```console
# VRT だけ作る（1,164 図郭でも 486KB・5秒）
$ grid2geotiff merge data/out -o mosaic.vrt --vrt-only

# GeoTIFF と、どう結合したかの記録としての VRT を両方
$ grid2geotiff merge data/out -o mosaic.tif --keep-vrt
  OK   1,600x1,800 @ 0.5m  被覆率 100.00%  -> mosaic.tif + mosaic.vrt
```

座標系・格子間隔・データ型・格子の位相が食い違う入力が混ざっていれば、結合せずエラーにする。

### validate — GeoTIFF が標準仕様に適合しているか点検する

```console
$ grid2geotiff validate data/out
仕様適合点検 6 ファイル
  OK   08LE2134.tif
  OK   08LE2135.tif
  OK   08LE2144.tif
  OK   08LE2145.tif
  OK   08LE2154.tif
  OK   08LE2155.tif

仕様適合点検: 適合 6 / 注意 0 / 不適合 0 / 計 6
```

条項から外れれば、理由と根拠を添えて報告する。

```console
$ grid2geotiff validate 08KD1629.tif
仕様適合点検 1 ファイル
  注意 08KD1629.tif
       注意 欠測率: 51.91%
            根拠 同 第5節運用基準「欠測率は国土基本図図郭単位で 10％以下を標準」

仕様適合点検: 適合 0 / 注意 1 / 不適合 0 / 計 1
```

**自分が変換したものだけでなく、受け取った GeoTIFF の点検にも使える。**

> 貸与されたデータからいきなりマップタイルを作成すると、貸与データに不足があること、Nodata が適切に設定されていない等の異常に事前に気づくことができず、出戻り作業が発生することも少なくない
> （[マップタイル作成マニュアル 第1.0版](https://forestgeo.info/250510_manual_maptiles_1.0.pdf)）

見る項目と根拠。

| 項目 | 不適合にする条件 | 根拠 |
|---|---|---|
| 形式 | GeoTIFF でない、位置情報を持たない | オープンデータ標準仕様書 Ver2.1 |
| バンド | 1バンドでない（32bit でなければ注意） | 同「非圧縮、32bit を基本とする」 |
| 圧縮 | 非可逆圧縮 | 同「圧縮する場合は可逆性がある方式」 |
| 格子間隔 | 1m 超、または X と Y が違う（0.5m 以外は注意） | 標準仕様書 Ver3.1「1m 以下」 |
| 座標系 | （平面直角座標系でなければ注意） | オープンデータ Ver2.1「原則、最新の平面直角座標系」 |
| NoData | -9999 でない、設定がない | マップタイル作成マニュアル「ラスタ値は -9999 に統一」 |
| 図郭 | 図郭の範囲に収まらない、格子に載らない | 地理院 DEM 作成マニュアル（案）第2条 |
| 標高値の刻み | （1cm より細かければ注意） | 同 第8節「１cm 単位を四捨五入して 0.1m」 |
| 欠測率 | （10% 超なら注意） | 同「国土基本図図郭単位で 10％以下を標準」 |

**「〜とする」と言い切る条項に反すれば不適合、「基本とする」「標準とする」の幅から外れるだけなら注意にとどめる。** 後者を不適合にすると、現に配布されている正しいデータまで弾いてしまう。`-v` を付けると適合した項目も表示する。

| オプション | 既定 | 説明 |
|---|---|---|
| `-v, --verbose` | off | 適合した条項も1行ずつ出す |
| `-j, --jobs` | `1` | 並列処理数 |

## 入力形式

`X Y Z` を1行1点で並べたテキスト。

- 拡張子: `.txt` / `.csv` / `.xyz` / `.dat`、およびそれを1つだけ含む `.zip`
- 区切り: 空白 / カンマ / タブ / セミコロン（先頭行から自動判定）
- 改行: LF / CRLF どちらも可
- `#` で始まる行と空行は読み飛ばす
- 4列以上でもよい。X,Y,Z がどの列かは `--columns` で指定する

## 出力仕様

- GeoTIFF（タイル化、既定 256×256 ブロック、Deflate + 予測子2）
- 1バンド、バンド説明 `elevation`（データ型は既定 `float32`、`--dtype` で変更）
- NoData 既定 `-9999`（欠損セルに充填。マップタイル作成マニュアルの「ラスタ値は -9999 に統一」に準拠）
- `AREA_OR_POINT=Area`、`GRID_CONVENTION` / `GRID_RESOLUTION` / `SOURCE_FILE` タグ

## エラーが出たとき

どれも「黙って間違った成果物を作らない」ための停止なので、メッセージの指示に従えば進める。

| メッセージ | 何が起きているか | どうする |
|---|---|---|
| `ファイル名から CRS を判定できない` | ファイル名が図郭番号の形式でない | `--crs EPSG:6676` のように座標系を明示する |
| `図郭の範囲に収まらない` | ファイル名は図郭番号の形だが、座標がその図郭の外にある | 名前が本当に図郭番号か確かめる。違えば `--crs` を明示する |
| `格子が疎すぎる` | 格子間隔の推定を外している。**列の指定間違いが多い** | 5列のデータなら `--columns 1,2,3`。間隔が分かっていれば `--res 0.5` |
| `X 軸が格子に載っていない` | 点が規則格子に載っていない（不規則点群） | 内挿補間が要る作業なので、本ツールの対象外 |
| `格子が噛み合わない`（merge） | 結合しようとした図郭どうしが半セルずれている | 元データの作り方を確認する。混ぜて結合してはいけない |
| `入力が疎すぎる`（merge） | 離れた区画が混ざっていて、間を埋める巨大な空ラスタになる | 地域ごとに分けて結合する。意図通りなら `--min-coverage 0` |

詳しい理屈は [設計メモ](docs/design.md) にある。

## 開発

```console
pip install -e ".[dev]"
pytest -q
ruff check . && ruff format --check .
```

テストは実データを使わず、同じ性質（セル中心座標・欠損セル・CRLF）を持つ合成データで検証する。ただし図郭番号から計算する範囲の期待値だけは、実データ4枚の座標範囲から採っている。

実データでの検証手順・出所・ライセンスは [`testdata/README.md`](testdata/README.md) にまとめてある（山梨県 10 図郭、静岡県 ALB 1,164 図郭、山梨県全県 37,929 図郭）。

山梨県全県では、**配布元の GeoTIFF を正解データとして 17.69 億セルを突き合わせ、37,705 / 37,721 図郭が差 0 で一致**した。
