# 検証レポート

grid2geotiff を実データで検証した結果のまとめ（2026-09-28 時点）。個々の手順と生の数字は [`testdata/README.md`](../testdata/README.md) と各 issue にある。このレポートは、何を確かめ、何を確かめていないかを一覧できるようにしたものである。

自動テスト（`pytest`）は合成データで完結しており、ここで扱う実データは使わない。

## 要約

- **山梨県全県 DEM（37,929 図郭）を配布元の GeoTIFF と照合し、37,705 図郭（99.41%）でセル単位の完全一致を確かめた。** 位置・欠損・標高値のすべてが一致した。一致しなかった図郭にも、変換の誤りに由来するものはない
- **GDAL の XYZ ドライバと比べても、比べた 445 図郭すべてでセル単位の結果が一致した**（#29）
- **静岡県 ALB（1,164 図郭）は失敗 0 で変換できた。** 図郭記号 7 種類の CRS 判定、充填率の低い図郭、負の標高を確認した
- 結合（`merge`）は、小規模な区画で有効セル数が図郭の合計と一致することを確かめた。全県の結合結果を正解と照合する作業はまだ行っていない（#34）

## 1. 山梨県全県 DEM と配布 GeoTIFF の照合

山梨県は、同じ図郭の同じ格子を txt と GeoTIFF の両方で配布している。G空間情報センターの 18 データセットを調べたなかで、この条件を満たすのは山梨県だけだった（[`testdata/candidates.md`](../testdata/candidates.md)）。そこで配布 GeoTIFF を正解データとして、変換結果をピクセル単位で突き合わせた。

### データ

| 項目 | 内容 |
|---|---|
| 座標参照系 | JGD2011 平面直角座標系 第 VIII 系（EPSG:6676） |
| 図郭 | 1/500 図郭（400m × 300m）、37,929 図郭。1/50000 図郭の記号は 11 種類 |
| 格子 | 0.5m、1 図郭 800 × 600 セル |
| 入力 | txt の ZIP 81.3 GiB（展開すると 453.3 GiB）、17,713,253,059 点 |
| 正解 | 配布 GeoTIFF 67.0 GiB（float32、NoData 1.7014e38） |

### 処理

| 段階 | 結果 |
|---|---|
| 変換 | 成功 37,850 ／ 失敗 79。2,390 秒（`-j 8`）、ピークメモリ 1.37 GB、出力 19.4 GiB |
| 照合 | 37,721 図郭、有効セル 17.69 Gpx |

### 結果（母数 37,929 図郭からの内訳）

| 区分 | 図郭数 | 割合 | 内容 |
|---|---:|---:|---|
| **完全一致** | **37,705** | 99.41% | 大きさ・transform・CRS・欠損の位置・標高値がすべて一致 |
| 値の差あり | 16 | 0.04% | 位置と欠損は一致。標高値に最大 0.005m の差 |
| 大きさ違い | 129 | 0.34% | 配布元は 800×600、本ツールはデータの外接矩形。重なる部分の値は一致（#29 で確認） |
| 変換失敗 | 79 | 0.21% | 本ツールに出力がない（#26） |
| **計** | **37,929** | 100% | |

照合した図郭では、**欠損とみなすセルの集合が配布元と完全に一致した**。NoData の値は本ツールが -9999、配布元が 1.7014e38 で異なるので、値ではなくセルの集合で比べている。半セルずらしを誤れば transform の原点が 0.25m ずれて全件が食い違う。したがってこの一致は、座標の扱いが正しいことを配布元の成果物で裏づけている。

### 一致しなかった図郭の説明

**値の差（16 図郭、`08KD9429`〜`08KD9552`）は、配布テキストが 1cm に丸められていることで説明できる。** 配布 GeoTIFF は 1mm 単位の値を持っている。差の最大 0.005m は丸め幅のちょうど半分で、差があるセルの割合（約 90%）も、下 1 桁が 0 でないセルの割合と合う。XYZ ドライバでも同じ差が出た（#29）。ただし、テキストと GeoTIFF の値を突き合わせたのは 3 セルだけで、全セルでは確かめていない（#28）。

**大きさの違い（129 図郭）は、出力範囲の方針の違いによる。** 配布元は部分的にしか被覆していない図郭も図郭全体で出力する。本ツールはデータの外接矩形で切る。XYZ ドライバも外接矩形で切るので、本ツール独自の挙動ではない。格子を合わせて比べると、重なる部分は完全に一致した。配布元の側でも、重なりの外に有効なセルはなかった（#29）。

**変換失敗（79 図郭）の原因は、入力データ側の事情である。**

| 件数 | 原因 | 既存オプションでの回避 | 配布 GeoTIFF |
|---:|---|---|---|
| 76 | ZIP 内の txt が 0 バイト（整備外の図郭） | 回避できない | 全セル NoData |
| 2 | 片方の軸の座標が1種類で、格子間隔を推定できない（`08LD4359`、`08LE8450`） | `--res 0.5` | 有効 3 セル／2 セル |
| 1 | 充填率 0.855% が既定の下限 1% を下回る（`08LE8284`） | `--min-fill-ratio 0.005` | 有効 3,745 セル |

## 2. GDAL の XYZ ドライバとの比較（#29）

本ツールは、XYZ テキストの読み込みと格子の組み立てを pandas と numpy で自前実装している。GDAL の XYZ ドライバで同じ結果が出るかを確かめた（GDAL 3.9.3、rasterio 1.4.3 に同梱）。

| 区分 | 図郭数 | 結果 |
|---|---:|---|
| 無作為抽出（乱数の種 20260925） | 300 | 本ツール・XYZ ドライバ・配布 GeoTIFF の三者が完全一致 |
| 値の差あり | 16 | 本ツールと XYZ ドライバは完全一致。配布 GeoTIFF とは同じ差がある |
| 大きさ違い | 129 | 本ツールと XYZ ドライバは完全一致。重なる部分は配布 GeoTIFF とも一致 |
| 変換失敗 | 79 | XYZ ドライバも 78 件は開けない。`08LE8284` だけは開け、その結果は配布 GeoTIFF と一致 |

格子を組み立てる中核部分は、XYZ ドライバと結果が変わらない。違いが出るのは付帯情報である。

| 項目 | XYZ ドライバ | grid2geotiff |
|---|---|---|
| NoData | 欠損があれば 0.0、なければタグなし | 常に -9999 |
| CRS | 付かない | 図郭番号から判定して付ける |
| `AREA_OR_POINT` | 付かない | Area |

NoData が 0.0 だと、標高 0m と欠損を区別できない。静岡 ALB のように海面付近の標高を含むデータでは、値が壊れる。

処理速度は、1 図郭あたり本ツールが 379〜381 ms、XYZ ドライバが 392〜395 ms で、ほぼ同じだった。

## 3. 山梨県全県の結合

```console
$ grid2geotiff merge testdata/yamanashi-dem/out -o testdata/yamanashi-dem/merge.vrt --vrt-only
  OK   172,804x178,256 @ 0.5m  被覆率 58.09%  -> merge.vrt
```

86.4km × 89.1km、30.8 Gpx の範囲を、VRT 15.4MB・160 秒・ピークメモリ 282MB で結合できた。配布 GeoTIFF から作った VRT と大きさは同じだが、中身の照合はまだ行っていない（#34）。

## 4. 静岡県 ALB 全 1,164 図郭

山梨県とは性質の違うデータで、網羅性と頑健性を確かめた。列の並びが違うので `--columns 1,2,3` を指定している。

| 項目 | 結果 |
|---|---|
| 変換 | 成功 1,164 ／ 失敗 0。入力 988MB（ZIP のまま）、出力 123MB |
| CRS 判定 | 1,164 件すべて EPSG:6676。1/50000 記号 7 種類（ND/NE/OB/OC/OD/PC/PD） |
| 格子間隔の推定 | 1,164 件すべて 0.5m |
| 充填率 | 最小 4.34% ／ 中央 68.75% ／ 最大 100% |
| 標高 | 負値を含む（最小 -12.50m） |
| NoData | 1,164 件すべて -9999 |
| 全図郭の結合 | 被覆率 1.31% で弾かれる（期待どおり。通すと約 100GB のほぼ空のラスタになる） |
| ブロック単位の結合 | `08PD13`（54 図郭）で、結合後の有効セル 11,043,678 が図郭ごとの合計と一致 |

ただし、このデータセットは測地系が JGD2024 とされており、JGD2011 の EPSG:6676 を付けてよいかは確かめていない（#31）。

## 5–6. 小規模な結合

- **甲府（連続 6 図郭）**: 結合後の有効セル 2,869,839 が、図郭ごとの合計と完全に一致した。図郭境界に隙間も重複もない
- **富士吉田（離散 4 図郭）**: 被覆率 66.67% の穴あき結合が通った。甲府の図郭と混ぜると被覆率 0.25% になり、弾かれた

## 分かった課題

| 課題 | issue |
|---|---|
| 空の txt 76 件を「失敗」ではなく「整備外」として区別する | #26 |
| 片方の軸の座標が1種類でも、もう一方の軸の間隔から推定する | #26 |
| `--min-fill-ratio` の既定 1% が実データ（0.855%）を弾いた。不規則点群の誤判定（実測 0.0004%）との間で既定値を決め直す | #26 |
| 図郭全体に合わせて出力する選択肢がない（129 図郭の大きさ違いの原因） | #26 |
| XYZ ドライバを使わない理由を `docs/design.md` に書く | #29 |
